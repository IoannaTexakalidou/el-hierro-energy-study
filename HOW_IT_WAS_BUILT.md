# How the study was built

This page explains how the code is organised and how I used AI to build it. The code itself is private, but I'm happy to walk through it on a call.

## Code architecture

The study is a Python pipeline of about 2,500 lines. One command, `python src/run_all.py`, rebuilds everything from the raw data: figures, the Excel workbook, the 17 page report and the slide deck. No number in the report is typed by hand. Every one is read from the model results, so a change in one input shows up everywhere at once.

```
config.py        every input value, each with its source written next to it
models.py        the physics and economics, shared by all steps
      |
01_download_data.py   grid operator data, weather, dust, cost catalogues, fuel prices
02_prepare_data.py    clean the data, fix time zones and gaps, build one hourly table
03_wind.py            turbine model, checked against the real wind farm
04_pv.py              solar panel model, checked against PVGIS
05_system.py          simulate 7,040 systems hour by hour, cost them, find the cheapest
06_report.py          Excel workbook and PDF report
07_slides.py          slide deck
```

**config.py.** The single place for inputs. Each value has its source on the same line, for example the Danish Energy Agency sheet and year it comes from. Where a source gives a range, the range is stored too and used in the sensitivity test.

**models.py.** Small functions that each do one job: wind speed at hub height, air density, turbine output from the power curve, panel temperature, dust on the panels, panel output, the hourly battery and diesel balance, and the yearly cost of a system. The step scripts only call these functions.

**The simulation.** The hourly balance is written with NumPy so that all 7,040 systems run through the 8,760 hours of the year together, as one array calculation, instead of one at a time in a loop. The full study runs in a few minutes on a laptop.

**Checks built in.** The wind and solar models are compared with real measurements before the system step uses them, and the results are rerun on a second weather year (2024) to make sure the answer does not depend on one year.

**Tools:** Python, pandas, NumPy, Matplotlib, openpyxl, python-pptx, PyMuPDF.

All the equations the model uses are written out in [FORMULAS.md](FORMULAS.md).

## How I used AI

I built this study together with an AI coding assistant (Claude, by Anthropic). The assistant wrote most of the Python code. My part was to decide what the study should answer, to keep every number tied to a published source, and to question results that did not make sense before accepting them.

We worked by three rules:

1. No number without a source. Every input lives in `config.py` next to its citation.
2. No model is used before it is checked against real measurements.
3. Everything is generated by code, so the report can never drift away from the results.

What I take from this: AI makes it possible to build a study of this size quickly, but the value comes from setting clear rules, checking the output against reality and understanding every step well enough to explain it.
